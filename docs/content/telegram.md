# Telegram

The Telegram backend uses the MTProto API to store files as document messages in
one chat. It uses a Telegram user account, not a bot token or the Bot API.

The default target is **Saved Messages** (`chat_id = me`). A public Telegram
username can be selected with `chat_id`, for example `@my_channel`. Numeric chat
IDs and private chats without a public username are not supported because they
need an access hash that cannot be derived from the ID alone.

Telegram chats do not provide a directory hierarchy to this backend. Each
remote is a flat namespace. If more than one message has the same document
filename, the newest message is exposed by that name. Uploading a replacement
sends a new document first and then deletes the old message; if the delete fails,
the backend reports the partial failure. Removing a remote deletes its Telegram
message. Use this backend only with chats where the configured account has the
required access and deletion permissions.

Telegram message dates do not represent a local file's modification time, and
the backend cannot preserve or set file modification times.

## Authentication

Create an API ID and API hash at <https://my.telegram.org>, then configure a
remote with `rclone config`. On the first sign-in, the backend requests the
account phone number and then prompts for the one-time code sent by Telegram. If
two-step verification is enabled, its password is requested with hidden terminal
input. These prompts require an interactive terminal; use the `phone`,
`auth_code`, and `twofa_password` options when supplying values explicitly. The
one-time code and 2FA password are cleared from the saved remote config after a
successful sign-in. A Telegram authorization session is saved in the rclone
configuration and reused on later runs. Protect the rclone configuration file
as it contains credentials that can authorize access to the account.

The backend does not accept updated Telegram terms of service automatically;
complete that step in the Telegram app before connecting again.

## Examples

List files in Saved Messages:

```sh
rclone lsf telegram:
```

Copy a file to a configured Telegram chat:

```sh
rclone copy ./backup.tar telegram:
```

### Standard options

Here are the Standard options specific to telegram (Telegram (MTProto)).

#### --telegram-api-id

Telegram API ID from https://my.telegram.org.

Properties:

- Config:      api_id
- Env Var:     RCLONE_TELEGRAM_API_ID
- Type:        string
- Required:    true

#### --telegram-api-hash

Telegram API hash from https://my.telegram.org.

**NB** Input to this must be obscured - see [rclone obscure](/commands/rclone_obscure/).

Properties:

- Config:      api_hash
- Env Var:     RCLONE_TELEGRAM_API_HASH
- Type:        string
- Required:    true

#### --telegram-phone

Phone number for the first sign-in, in international format. If empty, it is requested on an interactive terminal.

Properties:

- Config:      phone
- Env Var:     RCLONE_TELEGRAM_PHONE
- Type:        string
- Required:    false

#### --telegram-chat-id

Chat to use: 'me' for Saved Messages or a public username such as '@my_channel'.

Properties:

- Config:      chat_id
- Env Var:     RCLONE_TELEGRAM_CHAT_ID
- Type:        string
- Default:     "me"
